Leaf collections and scratch

Sampled and harmonic collections, receive wrappers, and the scratch types used for leaf multiplication. See Choosing leaf storage for the user-facing choices.

MLFMA.FarFields.CircularHarmonicAssembledCollection — Type
CircularHarmonicAssembledCollection

Either compressed 2-D collection whose coefficients were assembled and analysed, CircularHarmonicRadiationCollection or CircularHarmonicAssembledReceiveCollection.

Both types use the same scratch, order accessors, and kernels after analysis. The union excludes CircularHarmonicReceiveCollection, which reuses radiation coefficients and needs different kernels.

MLFMA.FarFields.CircularHarmonicAssembledReceiveCollection — Type
CircularHarmonicAssembledReceiveCollection(radiation)

A leaf's assembled receive patterns as circular-harmonic coefficients. This is the Petrov test side under CircularHarmonicLeafStorage.

Wraps a CircularHarmonicRadiationCollection whose coefficients were analysed from receiveoperator(op)'s patterns. The two types store patterns from different sides but use the same kernels, so this wrapper forwards to the radiation collection.

The separate <: AbstractReceiveFieldCollection type identifies the side for map constructors, scratch pools, and tests. See test/Maps/circularharmonicstorage.jl.

Unlike CircularHarmonicReceiveCollection, the Galerkin wrapper, this collection owns its receive coefficients. It applies neither antipodal parity nor the operator's receive coupling. It needs no mirrorrule or receivecouplingrule, so it supports the Petrov-only 2-D double layers.

source
MLFMA.FarFields.CircularHarmonicLeafScratch — Type
CircularHarmonicLeafScratch(synthesis, mirror, coefficients, samples, leaves, ncomponents)

The per-(level, chunk) working set for a circular-harmonic leaf multiply.

As with SphericalHarmonicLeafScratch, some fields are shared and others are mutable scratch:

  • synthesis and mirror depend only on the level's grid and order. Leaves share them by reference. mirror is S with the (-1)^m antipodal parity folded in (see mirrorsynthesis), which is what the Galerkin receive side uses instead of a mirror-index permutation.
  • coefficients and samples are genuine scratch, sized for the largest batch this chunk will multiply.

No quadrature weights are stored here. MLFMA's sampled leaf scatter transposes its collection without weights at the leaf; angular quadrature is applied in translation. A receive kernel written as Sᴴ W would satisfy a weighted pairing but would not match the sampled path.

source
MLFMA.FarFields.CircularHarmonicLeafScratch — Method
CircularHarmonicLeafScratch(t, ncomponents; ngroups=1)

Build the scratch for a level whose transform is t, for moments of ncomponents components, sized to multiply ngroups leaves at once.

Takes no sampling: unlike the spherical case there is no frame to tabulate, so the transform alone determines everything the level shares.

MLFMA.FarFields.CircularHarmonicRadiationCollection — Type
CircularHarmonicRadiationCollection(storage)

A leaf's radiation patterns as circular-harmonic coefficients.

storage is a CircularHarmonicStorage whose columns are this leaf's basis functions in the order H2Trees.values(tree, leaf) gives, the same order a sampled collection's columns are in, so the two are interchangeable from the traversal's point of view.

D is the storage's own component count, NOT a fixed number. The spherical collection declares 2 while storing 3, because its Cartesian representation is internal; here the stored components are the produced ones, so a ScalarFarField map gets D = 1 and the 2-D hypersingular's PlanarVectorScalarFarField gets D = 3 from the same type.

source
MLFMA.FarFields.CircularHarmonicReceiveCollection — Type
CircularHarmonicReceiveCollection(radiation, coupling)

The Galerkin receive collection for a leaf whose radiation patterns are stored as circular-harmonic coefficients.

Holds a reference to the radiation collection and the operator's coupling. The antipodal mirror is a per-mode sign folded into the level's scratch.mirror, so unlike the sampled LazyReceiveFieldCollection there is no index array and no mirror pass.

MLFMA.FarFields.SphericalHarmonicLeafScratch — Type
SphericalHarmonicLeafScratch(synthesis, mirror, θ̂, φ̂, coefficients, cartesian, leaves)

The per-(level, chunk) working set for a spherical-harmonic leaf multiply.

The fields have two roles:

  • synthesis, mirror, θ̂, φ̂ depend only on the level's direction grid and order. Leaves share them by reference. synthesis is S; mirror is S with the (-1)^l parity folded in (see mirrorsynthesis), which is what the Galerkin receive side uses instead of a mirror-index permutation.

  • coefficients and cartesian are genuine scratch, sized for the largest batch this chunk will multiply, one group for the per-node path, the whole chunk for the batched one.

No quadrature weights are stored here. MLFMA's sampled leaf scatter transposes its collection without weights at the leaf; the sphere's quadrature is applied in translation. A kernel written as Sᴴ W would not match that contract. See this file's receive-side header.

MLFMA.FarFields.SphericalHarmonicRadiationCollection — Type
SphericalHarmonicRadiationCollection(storage)

A leaf's radiation patterns as spherical-harmonic coefficients.

storage is a SphericalHarmonicStorage with three (Cartesian) components, whose columns are this leaf's basis functions in the order H2Trees.values(tree, leaf) gives, the same order the sampled collection's columns are in, so the two are interchangeable from the traversal's point of view.

Declares D = 2: the moment it produces is a TangentialSphericalFarField. The three Cartesian components are an internal representation, not what this collection hands back.

MLFMA.FarFields.SphericalHarmonicReceiveCollection — Type
SphericalHarmonicReceiveCollection(radiation, coupling)

The Galerkin receive collection for a leaf whose radiation patterns are stored as spherical-harmonic coefficients.

Holds a reference to the radiation collection and the operator's coupling map. The antipodal mirror is a per-degree sign folded into the level's scratch.mirror, and the tangential component signs fall out of the frame projection, so unlike the sampled LazyReceiveFieldCollection, there is no index array and no mirror pass. MLFMA.FarFields.VectorSphericalHarmonicAssembledReceiveCollection — Type
VectorSphericalHarmonicAssembledReceiveCollection(radiation)

A leaf's assembled receive patterns over the tangential vector harmonics. This is the Petrov test side under VectorSphericalHarmonicLeafStorage.

Wraps a VectorSphericalHarmonicRadiationCollection whose X/Ψ coefficients were analysed from receiveoperator(op)'s patterns, so it holds this side's own data and every kernel forwards to the radiation one. The separate type exists so <: AbstractReceiveFieldCollection still says which side the collection is on. See the SHE twin's docstring, whose argument applies here verbatim.

Not VectorSphericalHarmonicReceiveCollection, which is the GALERKIN side: that one derives its patterns from the trial leaf's through the (-1)^l / (-1)^(l+1) family parities and the operator's receive coupling. This one applies neither.

MLFMA.FarFields.VectorSphericalHarmonicLeafScratch — Type
VectorSphericalHarmonicLeafScratch(t; ngroups=1)

The per-(level, chunk) working set for a tangential-harmonic leaf multiply.

Splits the same way SphericalHarmonicLeafScratch does. A/D and their parity-folded twins Aᵖ/Dᵖ depend only on the LEVEL's directions and order, so every leaf at a level shares them by reference; coefficients, θfield and φfield are genuine scratch sized for the largest batch.

FOUR SHARED MATRICES rather than SHE's two, because the receive side needs the parity-folded pair as well. They are not free but they are per level, not per leaf, and the order VSH needs is lower, so in practice this is smaller than the SHE pair it replaces.

A leaf's radiation collection over the tangential vector harmonics.

Interchangeable with SphericalHarmonicRadiationCollection and the sampled RadiationFieldCollection from the traversal's point of view: it declares D = 2 and produces a TangentialSphericalFarField. Unlike SHE it produces it DIRECTLY. There are no Cartesian components here, internal or otherwise.

MLFMA.FarFields.VectorSphericalHarmonicReceiveCollection — Type
VectorSphericalHarmonicReceiveCollection(radiation, coupling)

The Galerkin receive collection for a leaf stored as tangential vector harmonics.

Holds a reference to the radiation collection and the operator's coupling map. The antipodal mirror is (-1)^l on the X family and (-1)^(l+1) on Ψ, derived in vectorharmonics.jl and checked there against MLFMA.mirrorindices/mirrorrule, and both signs are already folded into the level's Aᵖ/Dᵖ blocks and the receive side's sign. So there is no index array, no mirror pass, and no separate set of receive coefficients.
