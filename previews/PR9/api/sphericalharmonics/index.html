Spherical harmonics

MLFMA.Harmonics.SphericalHarmonics — Module
MLFMA.SphericalHarmonics

Orthonormal complex spherical harmonics and the transform pair over a set of sampling directions.

MLFMA samples each leaf basis function's far-field pattern at the finest level's angular rate. The translation operator sets that rate for the whole box. An individual basis function has smaller support and needs less angular bandwidth. In a measurement at 105k unknowns, the leaf radiation collection used 66 % of a map's memory (5.0 GB of 7.6 GB). Storing harmonic coefficients instead compressed the patterns 10.4× at ε = 1e-4, for a 2.5× smaller map. This is Eibert's SE-MLFMA (2005).

The MLFMA grids do not change. Aggregation between levels, translation, and interpolation/anterpolation still use the ordinary tensor samplings. Harmonics appear only between the MoM basis and the leaf group. The far-field collections wrap the storage and transforms defined here.

This submodule can be tested without a tree or assembler. Orthonormality, Parseval, and closed-form low-order harmonics provide analytic checks. The submodule is not exported.

using MLFMA.SphericalHarmonics

t = SphericalHarmonicTransform(ComplexF64, sampling, 9)
a = analyze(t, F)             # F: samples (rows) x components (columns)
F′ = synthesize(t, a)         # back to samples
truncationorder(a, 1e-4)      # the order that tail actually needs

MLFMA.Harmonics.SphericalHarmonics.SHETAILFLOOR — Constant
SHETAILFLOOR

The smallest relative tail leveltruncationorder will ask for, 1e-7.

This is a numerical limit, not a safety margin. The tail criterion compares against τ², so τ = 1e-8 demands a relative energy below 1e-16, near round-off. Cancellation can keep the computed tail above that threshold, causing truncationorder to return the full degree. See the three ceiling values at ε = 1e-6 in the last column of benchmark/interpolation/shecalibration.jl.

MLFMA.Harmonics.SphericalHarmonics.SphericalHarmonicStorage — Type
SphericalHarmonicStorage(order, center, coefficients)

One group's basis-function far-field patterns, stored as spherical-harmonic coefficients instead of samples.

coefficients is ((order+1)² * ncomponents) × nbasisfunctions, with the row index running over (l, m) fastest and the component slowest – so column j reshapes to the (ncoeff, ncomponents) matrix of basis function j's expansion at no cost.

center is the expansion center the coefficients are referenced to. Patterns about a different center differ by exp(-iκ k̂·Δc), which is not a coefficient-space operation, so a group's coefficients can only be summed if they share this center – see aggregate!.

MLFMA.Harmonics.SphericalHarmonics.SphericalHarmonicStorage — Method
SphericalHarmonicStorage(t, patterns, center) -> storage

Analyse sampled patterns into coefficients. patterns is a vector, one entry per basis function, each ndirections × ncomponents on t's grid.

t must be a setup transform built on gausslegendregrid, not on an MLFMA leaf sampling. The coefficients here have to be the field's actual harmonic content, and the leaf grid's quadrature is not accurate enough for that (it needs ~4x the θ nodes; see transform.jl's header).

MLFMA.Harmonics.SphericalHarmonics.SphericalHarmonicTransform — Type
SphericalHarmonicTransform(C, directions, weights, P)
SphericalHarmonicTransform(C, sampling, P)

The synthesis matrix S[q, lm] = Y_lm(direction q) together with the quadrature weights w_q that define its adjoint, for maximum degree P and element type C <: Complex.

directions is any iterable of (θ, φ)-bearing points in the SAME linear order the sampled fields use; weights is one weight per direction. The sampling form reads both from MLFMA.sphericalsamplepoints, whose k̂[q] = (1, θ, φ) and whose linear ordering is the one far fields are stored in.

Read this file's header before choosing sampling: on an equidistant grid those weights are the O(h²) midpoint rule, not an exact one.

MLFMA.Harmonics.SphericalHarmonics.VectorSphericalHarmonicTransform — Type
VectorSphericalHarmonicTransform(C, θs, φs, weights, P)
VectorSphericalHarmonicTransform(C, sampling, P)

The tangential synthesis blocks A and D over a fixed set of directions, together with the quadrature weights that define the adjoint.

Synthesis writes the two TANGENTIAL components directly:

F_θ = A a + D b        F_φ = D a - A b

with a the X-family coefficients and b the Ψ-family ones, each of length numvshcoefficients(P). There is no Cartesian stage and no frame projection – unlike the scalar transform, whose output has to be projected onto θ̂/φ̂ after synthesis.

Read this file's header before choosing sampling, and transform.jl's before trusting its weights: on an equidistant grid they are the O(h²) midpoint rule.

MLFMA.Harmonics.SphericalHarmonics.aggregate! — Method
aggregate!(A, storage, x) -> A

A .= storage.coefficients * x – the group's aggregated expansion, A_g = Σ_j I_j a_j.

A is a vector of length numcoefficients(storage) * ncomponents(storage); reshape(A, ncoeff, D) is then the matrix synthesize wants.

Every column must share the storage's center for this sum to be meaningful. The caller is responsible for that agreement.

MLFMA.Harmonics.SphericalHarmonics.aggregatelevel! — Method
aggregatelevel!(F, A, t, storages, xs) -> F

Aggregate every group of a level and synthesise them all in ONE GEMM.

storages and xs are matched vectors over the level's groups; A is scratch of size (ncoeff, D * ngroups) and F receives (ndirections, D * ngroups), group g occupying columns ((g-1)D+1):(gD) in both.

The single trailing synthesize! is the whole reason this function exists rather than a loop calling synthesize per group: S is shared across the level, and re-streaming it per group is measurably worse than the sampled path it is meant to replace. See this file's header.

MLFMA.Harmonics.SphericalHarmonics.analyze — Method
analyze(t, F) -> a

Project sampled values onto the harmonics: a = Sᴴ (w .* F).

This is the exact adjoint of synthesize with respect to the weighted inner product, by construction rather than by a matching implementation. See this file's header for when that adjointness is all that is needed and when genuine quadrature exactness is required as well.

MLFMA.Harmonics.SphericalHarmonics.analyzelevel! — Method
analyzelevel!(B, t, G) -> B

Project a whole level's incoming fields onto the harmonics: B = Sᴴ (w .* G).

G is (ndirections, D * ngroups) as aggregatelevel! produces, and B receives (ncoeff, D * ngroups) in the same column layout. One GEMM for the level, for the same reason the forward direction batches: S is shared by every group.

MLFMA.Harmonics.SphericalHarmonics.degreeenergy — Method
degreeenergy(a) -> Vector

Total |coefficient|² per degree, summed over orders m and over the columns of a, returned as a 0:P-indexed-by-position vector (entry l+1 is degree l).

Meaningful as an error measure only because the harmonics are orthonormal: by Parseval it is the L²(S²) energy of the corresponding piece of the field.

MLFMA.Harmonics.SphericalHarmonics.gausslegendregrid — Method
gausslegendregrid(P; oversampling=1) -> (θs, φs, weights)

A spherical grid on which analysis up to degree P is EXACT: Gauss-Legendre in cos θ with P+1 nodes, times a 2P+2-point trapezoidal rule in φ, flattened φ-fastest to match the linear order MLFMA.sphericalsamplepoints uses.

Exact because the substitution x = cos θ removes the Jacobian entirely – ∮f dΩ = ∫∫f dx dφ – so a product of two harmonics of degree ≤ P is a polynomial of degree ≤ 2P in x and P+1 Gauss-Legendre nodes integrate it with no error at all.

This is NOT what MLFMA.sphericalsamplepoints gives you, and the difference is a factor of four in θ nodes. That one places Gauss-Legendre nodes in θ and carries sin θ in the weight, so its integrand is not polynomial and it has no exactness property – only spectral convergence. It reaches round-off around Nθ = 4(P+1) where this grid is there at Nθ = P+1. See this file's header for the measured numbers.

oversampling multiplies both counts, for the 2P-bandwidth setup integrand of a pattern whose own degree is only approximately known.

MLFMA.Harmonics.SphericalHarmonics.leveltruncationorder — Method
leveltruncationorder(coefficients, ε; tailfloor=SHETAILFLOOR) -> Int

The expansion order to keep for a whole LEVEL: the largest order any of its boxes needs.

coefficients is an iterable of per-box coefficient matrices, each (P+1)² × ncolumns.

All boxes in a level must use one order because the leaf multiply synthesises a whole chunk against one matrix S. The maximum supplies enough coefficients for every box in the batch.

τ = max(ε/100, tailfloor) uses a calibrated factor of one hundredth. Only three of the nine calibration configurations are valid: the other six have boxes below λ/4 halfsize, within MLFMA's low-frequency breakdown (see benchmark/interpolation/shecalibration.jl). On the valid cases, the rule never under-predicts and over-predicts by at most 1. All three share one box size, so dependence on box size remains unmeasured. Using τ = ε instead under-predicts by up to 3 orders, which silently spends the map's error budget: at λ/4 it picks P = 9, which benchmark/interpolation/sheaccuracy.jl measures at 15 % worse far-field error than the sampled path, where P = 10 is indistinguishable from it. Under-prediction is the dangerous direction, so the rule is deliberately biased against it. Full table in benchmark/interpolation/shecalibration.jl.

MLFMA.Harmonics.SphericalHarmonics.lmindex — Method
lmindex(l, m) -> Int

1-based contiguous index of mode (l, m): l² + l + m + 1.

Modes are ordered by increasing degree, and within a degree by increasing order, so every mode of degree ≤ P occupies 1:(P+1)² exactly and truncating an expansion is a view rather than a gather.

MLFMA.Harmonics.SphericalHarmonics.mirrorsynthesis — Method
mirrorsynthesis(t) -> Matrix

t's synthesis matrix with the parity sign folded in: S⁻[q, lm] = (-1)^l S[q, lm], so S⁻ a evaluates the expansion a at the antipode of each of t's directions.

One matrix per LEVEL, shared by every group there – the same sharing that makes the forward synthesis worth batching. Precomputing it costs (P+1)²·NΩ complex numbers (2.4 MB at P = 9, NΩ = 1568) and saves applying the sign per group per matvec.

MLFMA.Harmonics.SphericalHarmonics.numvshcoefficients — Method
numvshcoefficients(P) -> Int

Coefficients per FAMILY in a tangential expansion of maximum degree P: (P+1)² - 1 = P(P+2).

A full expansion carries two of these, one for X and one for Ψ, so 2P(P+2) in total – against 3(P+1)² for the Cartesian scalar expansion of the same field. See this file's header for what that is worth in practice, which is more than the ratio suggests.

MLFMA.Harmonics.SphericalHarmonics.parity — Method
parity(P) -> Vector{Int}

(-1)^l at every coefficient index of an order-P expansion – the antipodal map k̂ -> -k̂ in coefficient space.

Scaling an expansion by this and synthesising gives the pattern evaluated at the ANTIPODE of every direction, which is what the Galerkin receive side needs from the radiation coefficients. See this file's header for why that replaces both MLFMA.mirrorindices and the mirrorrule component table.

MLFMA.Harmonics.SphericalHarmonics.project! — Method
project!(F, C, θ̂, φ̂) -> F

Project a synthesised Cartesian pattern onto the spherical frame, keeping the two TANGENTIAL components: F[:, 2g-1] = θ̂ ⋅ C[:, 3g-2:3g] and F[:, 2g] = φ̂ ⋅ C[:, 3g-2:3g].

C is (ndirections, 3 * ngroups) as a batched synthesis produces – group-major, component-minor – and F receives (ndirections, 2 * ngroups) in the matching tangential layout, which is also the order consecutive TangentialSphericalFarField moments occupy in H2Factory's moment arena.

Single-threaded; project threads over groups. Which to call is a size decision, not a preference – see benchmark/interpolation/shewrite.jl.

MLFMA.Harmonics.SphericalHarmonics.projectthreaded! — Method
projectthreaded!(F, C, θ̂, φ̂) -> F

project! with the group loop threaded. Groups write disjoint columns of F, so this needs no synchronisation.

Threading is useful for large batches. The synthesis GEMM uses BLAS threads, leaving projection as the serial part of the leaf multiply. Threading it measured a 2.1x speedup at 272 groups. At one group the spawn overhead alone costs 0.824 ms against 0.122 ms here, so the caller must choose by size.

MLFMA.Harmonics.SphericalHarmonics.truncatecoefficients — Method
truncatecoefficients(a, P) -> AbstractMatrix

The degree-≤ P part of an expansion: the first (P+1)² rows.

A plain row slice because of how lmindex orders things – l² + l + m + 1 puts every coefficient of degree ≤ P in the leading (P+1)² entries – so truncating needs no gather, and one analysis at a generous order serves every candidate order below it.

source
MLFMA.Harmonics.SphericalHarmonics.truncationorder — Method
truncationorder(a, ε) -> Int

Smallest P whose discarded tail holds less than ε² of the total energy: Σ_{l>P} energy / Σ_l energy < ε².

The squaring is deliberate – ε is a relative error on the FIELD, and energy is quadratic in it, so this returns the order at which the reconstruction is accurate to about ε. Returns the full degree present in a if no smaller order qualifies, and 0 for an all-zero expansion.

source
MLFMA.Harmonics.SphericalHarmonics.vshanalyze — Method
vshanalyze(t, Fθ, Fφ) -> (a, b)

The adjoint of vshsynthesize! against t's weights:

a = Aᴴ W F_θ + Dᴴ W F_φ        b = Dᴴ W F_θ - Aᴴ W F_φ

The tangential basis is orthonormal, so this recovers the coefficients exactly when the grid's quadrature resolves degree 2P. On other grids it remains the weighted adjoint of synthesis, not a separately implemented inverse.

MLFMA.Harmonics.SphericalHarmonics.vshauxiliaries! — Method
vshauxiliaries!(Y, D, A, P, θ, φ) -> (Y, D, A)

Fill the scalar harmonics Y_lm(θ, φ) and the two tangential building blocks at that direction, every buffer of length (P+1)² and indexed by lmindex:

  • D[q] = ∂_θ Y_lm / √(l(l+1))
  • A[q] = -i m Y_lm / (√(l(l+1)) sinθ)

θ must not be a pole; see this file's header.

The θ-derivative comes from a recurrence on the ALREADY-NORMALIZED Legendre functions, for the same reason ylm! does – forming P_l^m and its normalization separately overflows and underflows at the same factorial rate. Starting from (1-x²)dP/dx = (l+m)P_{l-1}^m - l x P_l^m and the ratio N_lm/N_{l-1,m} = √((2l+1)(l-m)/((2l-1)(l+m))):

sinθ ∂_θ P̄_l^m = l cosθ P̄_l^m - √((2l+1)(l²-m²)/(2l-1)) P̄_{l-1}^m

Both terms carry e^{imφ} unchanged, so the recurrence applies to Y directly and no separate Legendre table is needed.

MLFMA.Harmonics.SphericalHarmonics.vshindex — Method
vshindex(l, m) -> Int

1-based contiguous index of the tangential mode (l, m): l² + l + m.

The scalar lmindex shifted down by one, because there is no l = 0 tangential mode – a constant on the sphere has no surface gradient. Modes stay ordered by increasing degree, so truncating an expansion to degree P is still a row slice rather than a gather.

MLFMA.Harmonics.SphericalHarmonics.vshleveltruncationorder — Method
vshleveltruncationorder(pairs, ε; tailfloor=SHETAILFLOOR) -> Int

The order a LEVEL needs: the maximum over its leaves of vshtruncationorder, read at τ = max(ε/100, tailfloor).

pairs is one (a, b) tuple per leaf, which is exactly what vshanalyze returns.

The factor ε/100 and the floor come from the scalar rule, not an independent VSH calibration. See leveltruncationorder for the calibration's limits. A per-leaf tail bound alone does not bound the full map's error. The floor avoids asking for a tail below round-off, which can force the analysis order to be retained.

ONE ORDER PER LEVEL, not per leaf, because the batched leaf multiply synthesises a whole chunk against one pair of blocks – a ragged order has no shared B.

MLFMA.Harmonics.SphericalHarmonics.vshmirrorblocks — Method
vshmirrorblocks(t) -> (Aᵖ, Dᵖ)

t's synthesis blocks with the antipodal parity folded in, Aᵖ = A·diag((-1)^l) and likewise D.

The tangential counterpart of mirrorsynthesis and used the same way: the Galerkin receive collection is the radiation one with these blocks substituted, so it stores no data of its own. The sign PATTERN differs from the plain synthesis as well – see vshsynthesize! – because the two families pick up opposite signs.

MLFMA.Harmonics.SphericalHarmonics.vshparity — Method
vshparity(P) -> Vector{Int}

(-1)^l per tangential coefficient index, the antipodal map's action on the X family. The Ψ family takes the negative of this.

DERIVED, and then checked against MLFMA.mirrorindices/mirrorrule in test/SphericalHarmonics/. Under θ -> π-θ, φ -> φ+π: Y -> (-1)^l Y, ∂_θY -> -(-1)^l ∂_θY, and sinθ is unchanged. Feeding that through the component formulas together with the tangential mirror rule (θ̂ even, φ̂ odd) gives a' = (-1)^l a, b' = (-1)^(l+1) b.

MLFMA.Harmonics.SphericalHarmonics.vshsynthesize! — Method
vshsynthesize!(Fθ, Fφ, t, a, b; mirrored=false) -> (Fθ, Fφ)

F_θ = A a + D b, F_φ = D a - A b – the tangential field of an expansion, written straight into its two component arrays.

a and b may be vectors (one expansion) or matrices (one per column, which is the batched form the leaf multiply uses).

With mirrored=true the ANTIPODAL field is produced instead, F(-k̂) with the tangential mirror rule already applied. That is a per-degree sign and not a permutation:

a' = (-1)^l a        b' = (-1)^(l+1) b

so folding it into the blocks flips the sign pattern to F_θ = Aᵖ a - Dᵖ b, F_φ = Dᵖ a + Aᵖ b with Aᵖ = A·diag((-1)^l). See vshmirrorblocks for the folded blocks themselves, which is what the receive collection actually uses – this keyword exists for tests that want the identity stated in one place.

MLFMA.Harmonics.SphericalHarmonics.vshtruncationorder — Method
vshtruncationorder(a, b, ε) -> Int

Smallest degree P whose relative error, measured by the square root of the tail energy fraction, is at most ε:

ε_P² = Σ_{l>P} (|a_lm|² + |b_lm|²) / Σ_l (|a_lm|² + |b_lm|²)

The tangential analogue of truncationorder, and the same measurement Borries uses for the scalar case. Returns the full degree if no truncation meets ε.

ylm(l, m, θ, φ) -> Complex
