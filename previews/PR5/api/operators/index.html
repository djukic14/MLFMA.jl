Operators

The kernels MLFMA assembles, and the per-operator far-field type table.

MLFMA.Operators — Module
MLFMA.Operators

Define each BEAST operator's far-field representation, radiation and receive operators, coupling, and store rule. Also provide wrappers for operators BEAST does not supply.

This layer owns the operator property tables and store-rule types. It depends on FarFields for representation types, ComponentMap and fielddim; FarFields does not depend on this layer.

Seams declares farfieldtype, radiationfieldcollectiontype and receivecouplingrule so far-field kernels can call them during multiplication. This module imports those functions and defines their methods. It also extends interpolationtrait, which Interpolation owns.

farfieldstorerule needs no declaration in Seams: its other consumers are the collection builders in Assembly, which can depend on this layer directly.

MLFMA.Operators.AbstractFarFieldStoreRule — Type
AbstractFarFieldStoreRule

How a raw BEAST far-field value is projected into the moment layout farfieldtype(op) names.

A rule is a value, not a storer type: the same rule applies whether the moments are one flat block (the non-tree assembler path) or one block per leaf, and whether or not a trigonometric frame cache is needed. FarFieldStorer holds a rule plus that state.

MLFMA.Operators.StoreAsFarFieldValue — Type
StoreAsFarFieldValue()

Write BEAST's value directly, component by component, without a projection or frame cache. Scalar Helmholtz operators use this rule because their far-field values already match the stored moments. It serves the same purpose as H2Factory.StoreAsIs within MLFMA's rule-based storer.

MLFMA.Operators.StoreCartesianAsRadialScalar — Type
StoreCartesianAsRadialScalar()

Project a Cartesian 3-vector onto the spherical frame and keep only the radial component, giving a single scalar. Used by MWHyperSingular3D.

This stores a ScalarFarField, exactly like the Helmholtz scalar operators, but reaches it by projection rather than by StoreAsFarFieldValue. The layout does not determine the rule.

MLFMA.Operators.StoreCartesianAsSphericalVector — Type
StoreCartesianAsSphericalVector()

Project a Cartesian 3-vector onto the full spherical frame, keeping all three components (r, θ, φ). Used by MWSingleLayer3D, which stores a SphericalVectorFarField.

source
MLFMA.Operators.StoreCartesianAsTangentialSpherical — Type
StoreCartesianAsTangentialSpherical()

Project a Cartesian 3-vector onto the spherical frame and keep only the tangential components (θ, φ), discarding the radial one. Used by MWEFIE3D, MWDoubleLayer3D and DoubleLayerRotatedMW3D, which store a TangentialSphericalFarField.

MLFMA.Operators.StoreDoubleCartesianAsPairedSpherical — Type
StoreDoubleCartesianAsPairedSpherical()

Project a pair of Cartesian 3-vectors, packed back to back in one 6-element value, onto the spherical frame – giving six components. Used by BEAST.HH3DHyperSingularFDBIO, which stores a PairedSphericalVectorFarField.

MLFMA.Operators.checklazyreceive — Method
checklazyreceive(op)

Warn if op has no mirrored receive side, which a Galerkin matvec needs. See haslazyreceive.

Warn rather than raise because aggregation does not need the receive rule. test/Maps/aggregation.jl uses such a Helmholtz map without disaggregating. A full matvec would fail with a MethodError when the traversal first needs the rule.

maxlog=1 for the same reason checkboxsizes uses it: one clear notice, not one per map in a sweep.

MLFMA.Operators.farfieldstorerule — Method
farfieldstorerule(op)

The AbstractFarFieldStoreRule for op's leaf far-field assembly.

This projection table is independent of farfieldtype(op): a layout does not determine how raw values are projected into it. See the note at the top of this file.

MLFMA.Operators.haslazyreceive — Method
haslazyreceive(op) -> Bool

Whether op has a mirrored (lazy) receive path, i.e. a receivecouplingrule method.

DoubleLayerRotatedMW3D, HH3DDoubleLayerFDBIO and HH3DDoubleLayerTransposedFDBIO lack this rule. Petrov maps support them through an assembled receive side (receiveoperator); errors against a dense reference on a 1.2λ sphere were 2.6e-05, 3.9e-05 and 4.0e-05 respectively. The 2-D double layer and its transpose also lack a mirrored receive rule.

A full Galerkin matvec needs this rule because it mirrors the test side instead of assembling it. The lazy collection resolves the rule during multiplication, so a missing method fails there. checklazyreceive warns at construction; aggregation alone remains usable.
