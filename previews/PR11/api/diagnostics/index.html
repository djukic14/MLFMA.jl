Interpolation diagnostics

Measuring interpolation error on its own, against closed-form harmonics and with no tree or operator in the way.

MLFMA.Interpolation.InterpolationDiagnostics — Module
MLFMA.InterpolationDiagnostics

Estimate the error MLFMA's angular interpolation introduces, in isolation from everything else.

This module measures angular interpolation error, excluding BEAST quadrature, addition-theorem truncation, translation, near-field interactions, and tree construction. It evaluates the exact angular function independently on both grids. No mesh, operator assembly, or interpolated reference enters the comparison.

Reach it as MLFMA.InterpolationDiagnostics, or bind it:

using MLFMA
const ID = MLFMA.InterpolationDiagnostics

source = MLFMA.SphericalSampling{Float64}(28, 56)
target = MLFMA.SphericalSampling{Float64}(56, 112)
interpolator = MLFMA.SphericalLagrangeInterpolator{8}(ComplexF64, Float64)

cases = [
    ID.HarmonicCase(; l=10, m=0),
    ID.HarmonicCase(; l=10, m=5),
    ID.HarmonicCase(; l=10, m=10),
    ID.RandomBandlimitedCase(; L=10, seed=0x1234),
]

study = ID.interpolationerror(interpolator, source, target, cases)

ID.summary(study)
ID.worstcase(study)

Sampling pairs, not trees

The API takes two explicit MLFMA.SphericalSamplings because that is the whole of what interpolation depends on: a source grid, a target grid, and an interpolator. A caller who wants the grids a real tree would use can get them from MLFMA.sampling(γ, ε, tree; level) and pass them in; this module owns no tree convenience wrapper, so the diagnostic cannot quietly start depending on tree construction – one of the error sources it exists to exclude.

Field Representations

interpolationerror supports MLFMA.ScalarFarField and MLFMA.TangentialSphericalFarField. Use scalar cases for scalar fields and tangential harmonic cases for tangential fields. Other representations are rejected: their exact cases must respect their own continuation rules and supply every component, including the radial component of a spherical vector field.

Plotting

Nothing here loads PlotlyJS. Pointwise fields and rows are plain arrays and NamedTuples, so any plotting package can consume them; examples/plot_interpolation_diagnostics.jl shows one way, and the MLFMAPlotlyJS extension adds ploterror/plotcurves when PlotlyJS is loaded.

AnyCase

The case types this module knows how to evaluate exactly.

A Union rather than an abstract type with subtypes: the set is closed on purpose, so adding a case type is a deliberate edit here (and to exactvalue or fillexact!) rather than something that silently type-checks and then fails at evaluation.

MLFMA.Interpolation.InterpolationDiagnostics.HarmonicCase — Type
HarmonicCase(; l, m)

A single spherical harmonic $Y_l^m$ as the exact angular function to interpolate.

The sharpest diagnostic available: a single harmonic has one known bandwidth, so the error it produces is attributable to that degree alone rather than to a mixture. l fixes how fast the function oscillates and m fixes in which direction, which is why the harmoniccases families vary m at fixed l – an interpolator that is separable in θ and φ does not treat $m = 0$ and $m = l$ alike.

Arguments

  • l: harmonic degree, l >= 0
  • m: harmonic order, abs(m) <= l

MLFMA.Interpolation.InterpolationDiagnostics.InterpolationErrorResult — Type
InterpolationErrorResult

One case's interpolation error: the case, the two grid sizes, its bandwidth, the global metrics and the pointwise error fields.

Grid sizes use (Nθ, Nφ), not Base.size(sampling). The pointwise arrays keep the far field's storage shape, (Nφ, Nθ), with φ as the fast axis.

l, m and L are nothing for the case kinds that do not define them, so rows can produce uniform NamedTuples across mixed studies.

THREE VIEWS OF THE SAME ERROR, and which one gates a decision matters:

  • rel_l2, rel_linf, max_abs – combined over all components, with the same meaning as the single-component metrics.
  • component_rel_l2, component_rel_linf – per component, in component order. PRIMARY for a tangential field: poloidal harmonics have a 1/sinθ factor in Fφ; toroidal harmonics swap the component roles. Combined metrics can hide this asymmetry. A zero reference component (a poloidal m = 0 field's Fφ) reports 0 when its error is zero too and Inf otherwise.
  • vector_rel_l2, vector_rel_linf – of the pointwise tangent-vector magnitude. ATTRIBUTION ONLY: they say whether a componentwise spike is a real field error or the coordinate representation amplifying near a pole. Production interpolates the component arrays, so these must not be the number a policy is decided on. Note vector_rel_l2 == rel_l2 identically – the same sum grouped two ways – so the attribution value is in vector_rel_linf, the per-component pair, and the θ-band profile, not in the L2 numbers.

MLFMA.Interpolation.InterpolationDiagnostics.InterpolationErrorStudy — Type
InterpolationErrorStudy

A vector of InterpolationErrorResults plus the metadata they share.

The metadata holds what was held FIXED across the study, so a result never has to restate it and two studies cannot be compared without their conditions being visible:

  • stages – one NamedTuple per interpolation stage, each with that stage's interpolator, stencilsize, sourcesize and targetsize. A single-stage study has one entry; a chain (see intermediatesampling) has one per link.
  • stencilsizes – the stages' stencil sizes, in order, for tabulating.
  • interpolationtrait, farfieldtype – the trait the interpolation actually ran under, and the representation it ran on.
  • sourcesize, targetsize – the ENDPOINTS, (Nθ, Nφ) each: the first stage's source and the last stage's target. Any intermediate grid is in stages, not here.
  • supporteddegree – of the source grid, the ρ denominator.

There is deliberately no singular interpolator/stencilsize pair: a chain has no single stencil size, and a field reporting the first stage's would label a pθ = 20, pφ = 8 study as {20}. Read only(stages) for a single-stage study.

MLFMA.Interpolation.InterpolationDiagnostics.RandomBandlimitedCase — Type
RandomBandlimitedCase(; L, seed=0x12345678, decay=:none)

A random superposition of every harmonic up to degree L, as the exact angular function.

Complements HarmonicCase: a single harmonic can flatter an interpolator that happens to resolve one direction of oscillation well, while a full band exercises every (l, m) at once and is closer in character to an actual far field. seed makes it reproducible – two runs of the same case compare a bit-identical function, which is what lets a study be a regression baseline rather than a sample.

decay weights the coefficients by degree, since a physical far field is not white across the band:

  • :none – every degree weighted equally, the harshest of the three
  • :inverse_l – weight 1 / (1 + l)
  • :inverse_l2 – weight 1 / (1 + l)^2

Arguments

  • L: highest degree in the band, L >= 0
  • seed: seed for the coefficient draw
  • decay: one of :none, :inverse_l, :inverse_l2

MLFMA.Interpolation.InterpolationDiagnostics.RandomTangentialBandlimitedCase — Type
RandomTangentialBandlimitedCase(; L, seed=0x12345678, decay=:none)

A random superposition of every poloidal AND toroidal harmonic up to degree L, as the exact tangential field.

The tangential counterpart of RandomBandlimitedCase, and wanted for the same reason: a single vector harmonic can flatter an interpolator that happens to resolve one direction well, while a full band mixes sectoral and non-sectoral content in one field the way a real far-field pattern does. Without it, tangential evidence rests on single modes while the scalar evidence has both – which is not a fair comparison to decide an interpolator policy on.

BOTH FAMILIES IN ONE FIELD, not two studies averaged: a physical far field is a superposition of poloidal and toroidal parts, and their Fθ/Fφ structure differs (they are component-swapped mirrors), so a mixture exercises interactions that neither family alone can.

L >= 1, since there is no degree-zero tangential harmonic. decay weights by degree exactly as the scalar case does.

Arguments

  • L: highest degree in the band, L >= 1
  • seed: seed for the coefficient draw
  • decay: one of :none, :inverse_l, :inverse_l2

MLFMA.Interpolation.InterpolationDiagnostics.TangentialHarmonicCase — Type
TangentialHarmonicCase(; kind, l, m)

A single vector spherical harmonic as the exact TANGENTIAL field to interpolate.

kind is :poloidal ($B_l^m = ∇_Ω Y / sqrt(l(l+1))$) or :toroidal ($C_l^m = r̂ × ∇_Ω Y / sqrt(l(l+1))$). Together the two families span every band-limited tangential field, i.e. exactly what a far-field pattern is – so these are the cases a TangentialSphericalFarField actually has to carry.

Why not two scalar harmonics in the two components: the interpolator continues both with VirtualExtensionFlipθSign, f(θ,φ) = -f(-θ,φ+π), and unrelated scalars do not satisfy that. A genuine tangential field does, automatically – see vectorharmonics.jl. Getting this wrong would measure the reference disagreeing with the continuation rule and call it interpolation error.

l >= 1: there is no degree-zero tangential harmonic.

Arguments

  • kind: :poloidal or :toroidal
  • l: harmonic degree, l >= 1
  • m: harmonic order, abs(m) <= l

MLFMA.Interpolation.InterpolationDiagnostics._relativeerror — Method
_relativeerror(errornorm, referencenorm)

errornorm / referencenorm, with the zero-reference cases defined rather than left to IEEE.

  • reference zero and error zero -> 0. The component is identically zero and was interpolated to identically zero, which is exact, not undefined. This case is REAL and unavoidable: a poloidal m = 0 field has Fφ ≡ 0 everywhere, and (l=1, m=0) is the simplest tangential case anyone would reach for first.
  • reference zero and error nonzero -> Inf. "Relative error against a zero reference" is genuinely unbounded, and Inf says so in a way a table or a log plot can display. Raising here instead would take down a whole study over one component of one case.
  • otherwise the quotient.

Centralized so per-component metrics cannot each invent their own convention. Note this is deliberately NOT what the whole-field guard in errormetrics does: a reference that is identically zero over EVERY component means the case evaluated to nothing on the target grid, which is a broken case rather than a zero component, and that still raises.

MLFMA.Interpolation.InterpolationDiagnostics.adjointpairingerror — Method
adjointpairingerror(interpolator, anterpolator, sourcesampling, targetsampling, cases;
                    farfieldtype=MLFMA.ScalarFarField, othercaseseed=0x5eed)

For each case, the error in an unweighted Hermitian pairing and the adjointness residual.

One NamedTuple per case, table-friendly like rows:

  • pairing – |<f_fine, g> - <f_coarse, A g>| / |<f_fine, g>|, where f_fine is the case evaluated exactly on the target grid and f_coarse on the source grid. The reference is exact resampling, not interpolation. Contracting against g can cancel contributions to the error.
  • adjointness – |<I f, g> - <f, A g>| / |<I f, g>|. A correctness invariant, expected at round-off. Reported so that a pairing number is never read without knowing whether the operator it came from is still the adjoint at all.
  • case, rho, bandwidth, casekind – as in rows.

g is a scalar RandomBandlimitedCase at the case's bandwidth, drawn from othercaseseed. Use scalar cases and ScalarFarField: the comparison field has no tangential counterpart here. A full band avoids the systematic zero pairings of single harmonics with different φ orders. The reported ratios divide by the pairing magnitudes without a zero-denominator guard.

Arguments

  • interpolator, anterpolator: a matched pair, e.g. from MLFMA.buildreverseoperators
  • sourcesampling, targetsampling: coarse and fine grids, as for interpolationerror
  • cases: one case or any iterable of them

MLFMA.Interpolation.InterpolationDiagnostics.componenterrormetrics — Method
componenterrormetrics(interpolated, exact)

Error of a MULTI-COMPONENT field, as a NamedTuple carrying three views of the same discrepancy.

interpolated and exact are iterables of per-component matrices (e.g. H2Factory.moments(farfield)).

  • rel_l2, rel_linf, max_abs – combined over all components, with the same definitions as in the single-component errormetrics.
  • component_rel_l2, component_rel_linf – per component, in component order. PRIMARY for a tangential field: poloidal harmonics have a 1/sinθ factor in Fφ, while toroidal harmonics swap the component roles. Combined metrics can hide that asymmetry. Zero-reference components follow _relativeerror – 0 when the error is zero too, Inf otherwise – which a poloidal m = 0 case needs, since its Fφ is identically zero.
  • vector_rel_l2, vector_rel_linf – of the pointwise VECTOR magnitude, i.e. treating each direction's components as one physical vector. ATTRIBUTION ONLY: it says whether a componentwise spike is a real field error or the coordinate representation amplifying near a pole. Never the number that gates a policy decision, because production interpolates the component arrays, not the vector.

vector_rel_l2 and rel_l2 are mathematically equal, though rounding can differ: sqrt(Σ_points Σ_components |e|^2) is the same sum either way you group it, so the combined L2 metric ALREADY is the physical vector L2 metric. The two genuinely differ only for linf (a max over components and points is not a max of vector magnitudes) and for the pointwise fields. So attribution lives in component_*, vector_rel_linf and the θ-band profile – not in the L2 pair.

abs_error and rel_error are pointwise fields of the VECTOR magnitude, which is what one would plot on a sphere; for a single-component field they reduce to the scalar case unchanged.

MLFMA.Interpolation.InterpolationDiagnostics.dnormalizedlegendre — Method
dnormalizedlegendre(l, m, θ)

$∂_θ$ of normalizedlegendre, by recurrence in the same fully normalized quantity.

∂_θ q_l^m = (1/2) [ sqrt((l-m)(l+m+1)) q_l^{m+1} - sqrt((l+m)(l-m+1)) q_l^{m-1} ]

At m = 0, the m - 1 neighbour is $q_l^{-1}$, equal to $-q_l^{1}$, not zero. The terms add and give $sqrt(l(l+1)) q_l^{1}$. Dropping the lower term would halve the derivative.

m must satisfy 0 <= m <= l; negative orders come from the reflection in vectorsphericalharmonic.

source
MLFMA.Interpolation.InterpolationDiagnostics.errormetrics — Method
errormetrics(interpolated, exact)

Global and pointwise error of interpolated against exact, as a NamedTuple.

Fields: rel_l2, rel_linf, max_abs, abs_error, rel_error.

Single-component form. For a multi-component representation use componenterrormetrics, which adds per-component and vector-magnitude views while keeping these three names meaning the same thing.

TWO KINDS OF NORMALIZATION, and they are not interchangeable:

  • The GLOBAL metrics divide by a norm of the whole reference. rel_l2 is norm(err) / norm(exact) and rel_linf is maximum(abs, err) / maximum(abs, exact). Both are well posed for any nonzero reference, which is why the summary and the worst-case ranking use them.
  • The POINTWISE rel_error divides each point by its own reference magnitude, floored at eps. Useful for a plot, because it shows where the error is large relative to the local signal – but a harmonic has genuine zeros, and near them a pointwise relative error is a ratio of two small numbers that says more about the zero than about the interpolator. The floor keeps such points finite instead of Inf/NaN, and it is a display convenience, not a metric: never rank or report accuracy from maximum(rel_error).

abs_error is stored alongside precisely so a reader has an unnormalized field to fall back on.

MLFMA.Interpolation.InterpolationDiagnostics.harmoniccases — Method
harmoniccases(degrees; families=(:axisymmetric, :mixed, :sectoral))

One HarmonicCase per (degree, family) pair.

The families pick m from l, which is the comparison worth making: at a fixed degree, how the error depends on the direction the function oscillates in.

  • :axisymmetric – m = 0, no φ dependence at all, so this isolates the θ interpolation
  • :mixed – m = round(Int, l / 2)
  • :sectoral – m = l, the fastest φ oscillation the degree allows

Called "families" rather than "modes" deliberately: mode already means something physical in an MLFMA, and these are diagnostic inputs, not modes of the operator.

Arguments

  • degrees: the l values to cover
  • families: any of :axisymmetric, :mixed, :sectoral

MLFMA.Interpolation.InterpolationDiagnostics.intermediatesampling — Method
intermediatesampling(sourcesampling, targetsampling)

The grid that sits between a θ stage and a φ stage: targetsampling's θ nodes, sourcesampling's φ nodes.

The Gauss-Legendre interpolators resample θ first, then φ. Interpolating onto this grid changes only θ because its φ nodes match the source's. Interpolating from it to targetsampling changes only φ. Use the ordinary production calls to measure these stages separately:

middle = intermediatesampling(source, target)

θonly = interpolationerror(interpolator, source, middle, cases)   # θ resampled, φ untouched
φonly = interpolationerror(interpolator, middle, target, cases)   # φ resampled, θ untouched
both  = interpolationerror([interpθ, interpφ], [source, middle, target], cases)

The last form measures an order split with pθ != pφ by passing two interpolators with different stencil sizes. With equal orders, the chain applies the same two stages as a single interpolation.

MLFMA.Interpolation.InterpolationDiagnostics.interpolationerror — Method
interpolationerror(interpolator, sourcesampling, targetsampling, cases; farfieldtype)
interpolationerror(interpolators, samplings, cases; farfieldtype)

Interpolation error of interpolator taking cases from sourcesampling to targetsampling.

The second form measures a CHAIN: samplings[i] -> samplings[i+1] by interpolators[i], so length(interpolators) must be length(samplings) - 1. The exact function is evaluated on samplings[1] and again on samplings[end], and the stages in between pass the interpolated field along – so the reference is still never itself interpolated, and the reported error is the whole chain's, including any error one stage introduces that a later stage amplifies. rho and supporteddegree refer to samplings[1], the grid the case actually starts on. See intermediatesampling for what chains are for.

Returns an InterpolationErrorStudy – also for a single case, which comes back as a one-element study rather than a bare result so that summary, rows, worstcase and pointwiseerror apply to whatever this function returned, without the caller having to know which arity produced it.

The interpolator is the PRODUCTION one, called through its ordinary interpolator(farfield, source, target) method. There is no reference interpolation path here on purpose: a diagnostic that compared production against a second implementation would report the difference between two pieces of this package rather than the error against the exact function.

Arguments

  • interpolator: any MLFMA.AbstractInterpolator
  • sourcesampling: the grid the far field is known on
  • targetsampling: the grid to interpolate onto
  • cases: one case, or any iterable of cases (see HarmonicCase, RandomBandlimitedCase, harmoniccases)
  • farfieldtype: ScalarFarField or TangentialSphericalFarField, with matching exact cases; other representations are rejected

Sampling families

AbstractSampling, not SphericalSampling, so the Equidistant family can be measured on the same axis as the Gauss-Legendre one – see benchmark/interpolation/benchmarks.jl group 11. Nothing in the path above is quadrature-specific: the exact function is evaluated at MLFMA.θs/MLFMA.φs and the error is a plain norm over grid points, so no weight ever enters.

Two helpers remain specific to SphericalSampling:

  • adjointpairingerror checks an unweighted Hermitian pairing and its adjoint relation. It does not evaluate a quadrature-weighted spherical integral.
  • intermediatesampling constructs a Gauss-Legendre intermediate grid for the θ-then-φ interpolators. It does not construct an equidistant intermediate grid.

MLFMA.Interpolation.InterpolationDiagnostics.normalizedlegendre — Method
normalizedlegendre(l, m, θ)

$sqrt((2l+1)/(4π) ⋅ (l-m)!/(l+m)!) ⋅ P_l^m(cos θ)$, the θ-dependent factor of $Y_l^m$.

Computed by recurrence in the fully normalized quantity rather than as an unnormalized P_l^m scaled afterwards. That matters beyond style: (l-m)!/(l+m)! and P_l^m each overflow well before their product does, so the scaled-afterwards form loses high degrees to Inf/Inf while the recurrence below stays bounded.

m must satisfy 0 <= m <= l; negative orders are handled by sphericalharmonic.

MLFMA.Interpolation.InterpolationDiagnostics.supporteddegree — Method
supporteddegree(sampling)

The sampling's design degree, MLFMA.cutoffparameter(sampling), not its single-field aliasing limit.

A grid built with NθNφ(L) has supporteddegree == L. Gauss-Legendre and equidistant samplings use the same inverse, ceil(Nθ/2) - 1, so equal angular counts give equal ρ labels. This helper accepts spherical samplings only; it does not choose the degree a physical level needs.

MLFMA.Interpolation.InterpolationDiagnostics.tangentialbandcoefficients — Method
tangentialbandcoefficients(case::RandomTangentialBandlimitedCase, ::Type{T}=Float64)

The coefficients of case, as (poloidal, toroidal) vectors drawn once from its seed.

TWO SEPARATE VECTORS RATHER THAN ONE COMBINED INDEX. The scalar _coefficientindex packs m ∈ -l:l for l = 0:L into 1:(L+1)^2 with no gaps; here there are two families AND l starts at 1, so a combined index would need an offset and a skipped degree-zero slot – two chances to be off by one, in code whose errors look like plausible fields. Each vector is instead indexed by the SCALAR _coefficientindex with its l = 0 entry left unused, which costs one complex number per family and cannot be misread.

The draw order is poloidal in full, then toroidal, each ascending in l then m, and it is part of what the seed means: reordering it silently changes every case with that seed.

MLFMA.Interpolation.InterpolationDiagnostics.vectorsphericalharmonic — Method
vectorsphericalharmonic(kind, l, m, θ, φ)

The tangential components (Fθ, Fφ) of $B_l^m$ (kind = :poloidal) or $C_l^m$ (kind = :toroidal), as a Tuple of two Complex.

l >= 1 is required: at l = 0 the surface gradient of a constant vanishes and the normalization $sqrt(l(l+1))$ is zero, so there is no degree-zero tangential harmonic to return and this raises rather than producing NaN.

Negative orders come from $B_l^{-m} = (-1)^m conj(B_l^m)$ componentwise – the surface gradient and $r̂ ×$ are both real-linear, so the scalar reflection carries through unchanged, and there is one code path to get right.

MLFMA.Interpolation.InterpolationDiagnostics.θbandprofile — Method
θbandprofile(study, i; bands=4)

Where the error sits in θ: the share of the total squared error in each band of θ rows, counted in from each pole.

Returns a NamedTuple of (north, south, rowsperband, nbands), where north[k] and south[k] are the fractions of the total squared error in the k-th band from θ = 0 and from θ = π. The two hemispheres are kept APART rather than summed: an asymmetry between them is what a sign error in the pole continuation would produce, and averaging the two would hide exactly that.

The binning is chosen per call rather than stored in the result.

Tangential components can be less smooth near the poles than the physical vector field. Compare component metrics and scalar profiles to investigate a concentration of error there; the profile alone does not identify its cause.

bands is the number of θ indices per band, with all φ samples included. The last band in each hemisphere includes its remaining interior indices. On an odd-sized θ grid, the central index is excluded from both hemispheres but included in the total used for normalization.
